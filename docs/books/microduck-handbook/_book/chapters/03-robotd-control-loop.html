第三章：50 Hz 控制循环怎样让鸭子站稳

robotd 是运行时里最重要的程序，因为它是唯一持续拥有运动硬件控制权的服务。一个 50 Hz 循环意味着每隔 20 毫秒左右，程序会读取身体、更新内部状态、运行策略并提交关节目标。它不是“每来一个网页请求就直接控制舵机”；用户请求只更新意图，周期循环才是执行动作的地方。

一个 tick 的顺序

把一次循环画成数据管道，会比读完整个 main.rs 容易：

伺服总线 / MuJoCo RemoteIo
          │ 关节位置、速度、IMU
          ▼
      DuckIo 读取
          │
          ▼
  模型与状态估计 ──脚底接触/里程计/姿态
          │
          ▼
  组装策略观测（61 个浮点数）
          │
          ▼
     ONNX 策略推理
          │ 14 个动作值
          ▼
   动作缩放、模式与意图
          │
          ▼
  限幅、跌倒与安全检查
          │
          ▼
伺服目标 / MuJoCo body server

实际源码会把配置、状态发布、策略加载和非运动行为穿插在这条主线上。定位实现可从 robotd/src/main.rs、duck-control/src/ 与 docs/design/robotd-design.md 开始；遇到实时延迟时，先看循环中哪些操作同步执行，不要假设所有功能都在一个线程里。

为什么策略不是直接碰串口

策略只对当前观测提出动作。控制层将动作转换为舵机目标，再统一经过约束与安全机制。这样同一套步态模型可以在不同模式下重用，安全逻辑也不需要相信每一个策略或上层应用都正确。

硬件总线由控制 I/O 层集中拥有。否则每个行为各自读写 UART，读到的状态可能来自不同时间，两个控制器还可能同时争抢同一个关节。串行总线也不是可以无限并行访问的资源；集中式读写使更新顺序可预测，并便于做超时和健康度判断。

观测与动作的维度

运行时和训练端共享一份重要约定。策略输入为 61 维，动作输出为 14 维。输入可分为：躯干坐标系陀螺仪 3 维、重力方向 3 维、14 个关节相对 home 的位置、14 个关节速度、上一轮的 14 个动作，以及 13 维命令向量。命令部分包含身体平移与偏航速度、头部姿态和躯干姿态。

3 gyro + 3 gravity + 14 joint position + 14 joint velocity
+ 14 previous action + 13 command = 61 actor inputs

14 actuated joints = 14 policy outputs

机器人身上有 15 个舵机编号，但强化学习关节动作只控制其中 14 个；嘴部舵机不进入这份步态网络的动作向量。这个区别很重要：舵机总数、策略关节数和观察向量长度不是一个数字。

控制健康与真实时间

仿真时策略和控制循环仍按墙钟时间工作。MuJoCo 若跑不到接近 50 Hz，控制器看到的身体变化和它以为的变化就不匹配。对平衡控制来说，仿真慢下来可能表现为掉帧和不稳定，不能简单当作“动画播放比较慢”。robotctl monitor 与 scripts/duck-sim realtime 用来观察循环频率、超时和身体健康状态。
